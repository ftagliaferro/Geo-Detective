# Devlog — 2026-11-17 — Phone layout

Feedback: "give me a phone version that plays the same — on my phone everything looks tiny".

## Why it was tiny
The UI was a 1280×720 canvas scaled to fit the window. On a portrait phone (≈390 CSS px wide) that is a 0.3× zoom: 15 px text ends up around 5 px.

## What changed (ADR-0013)
- **Phone detection** from the window size in CSS pixels (`devicePixelRatio` on the web). Phones get `content_scale_size` = CSS size, so text renders at its designed size, and a **single-column layout**: scrolling pages, stacked cards, full-width buttons (≥ 44 px), wrapping chips, shorter titles.
- **Travel on phones:** globe fixed on top (+/− buttons, pinch to zoom), country list scrolls, destination + *Fly* pinned at the bottom. Landscape: globe left, panel right.
- **Chases:** the game takes all the free room; *Start* always on screen; smaller HUD on narrow screens.
- **Overlays** (clue mini-games, events, cutscenes) fit the width (2×2 transaction grid, stacked receipts) and get shorter pictures in landscape.
- **Rotation** rebuilds the current screen for the new shape (never mid-overlay, mid-flight or mid-chase).
- **Touch scrolling** from anywhere, even starting on a button; once the finger moves, the button is not pressed. Taps work as before.

## Bugs found on the way
- Money "order the transactions" mini-game was wider than a phone (4 cards in a row) → 2×2 on phones.
- Dubai (Spanish) and Los Ángeles city banners overflowed at 360 px → the row wraps on phones.
- On touch screens, changing screen from a button removed it mid-event; the browser's finger-up then hit a node outside the tree (engine error in the console). Old screens are now hidden and freed at the end of the frame.
- The touch scroller swallowed its own "cancel press" event (same device id) → drag-then-release still pressed the button. Caught by the new touch test.
- Two old console errors: an empty route arc on one-city results, and a 0-size "$" glyph on the first frame of the thief drawing.

## Verification
- `tests/ui_flows.gd -- --phone` (360×740) and `-- --landscape` (844×390): every case and escape played through the UI; on every screen and overlay, in both languages, nothing may stick out past the screen edge; touch drag/tap test. 8,617 checks each, plus the desktop run (6,995). All in CI.
- Real browser: the web export in headless Chromium emulating an iPhone 13 (DPR 3) — phone layout detected, tap, swipe-scroll and rotation checked.

## Same day — iPhone scrolling and a guided first case
**iPhone.** "Works well on Android; on iPhone scrolling is very bad." Root cause: Godot's web export uses the browser's `touch.identifier` as the touch index. Android numbers fingers 0, 1, 2…; iOS Safari uses large arbitrary ids. The drag-to-scroll only followed index 0, so on iPhone it never engaged (Godot's built-in scrolling doesn't start on buttons). It now follows whichever finger touched first. Also disabled iOS page gestures in the web shell (bounce, pinch/double-tap zoom, long-press callout). Proven in Chromium's iPhone emulation with iOS-style ids: the published build does not scroll, the new one does; the touch test now runs with both id styles (it fails on the old code).

**Intuitive for newcomers (ADR-0014).** First case and first escape come with a step-by-step guide: bubble + spotlight on the exact button, the first clue explained with its answer, board ✓/✗ explained, never blocking, state-driven, skippable. *How to play* and in-game hints rewritten in plain language. New `tests/tutorial_flow.gd`: following only the guide wins both modes in all three layouts.
